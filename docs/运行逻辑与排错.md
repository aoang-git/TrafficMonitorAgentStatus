# 运行逻辑与排错

本文面向需要了解显示规则或排查连接问题的用户。日常安装使用见 [README](../README.md)。

## 数据来源与状态

本插件通过 Agent Status Runtime 0.3.0 / schema 3 的只读 HTTP/SSE 接口接收活动，不读取 Agent 会话文件，也不安装 Agent Hook。Runtime 的当前下载入口为 [Releases](https://github.com/aoang-git/Agent_Status_Runtime/releases)。

| 显示结果 | 依据 |
|---|---|
| 工作中 | 新输入、消息、轮次开始，或外部 working |
| 调用工具 | 未结束的工具调用，或外部 tool_activity |
| 待确认 | 未解决的审批记录，或外部 waiting_confirmation |
| 任务完成 | 明确 completed 结束事件；Claude/Pi 满足静默结束规则；外部 completed |
| 任务中断 | 明确 interrupted/failed 结束事件，或对应外部上报 |
| 状态未知 | 来源降级、不明确的结束、无进展超时、手动清除采集提醒，或外部 unknown |

Codex 和 DeepSeek 的文件记录提供明确轮次结束；Claude 和 Pi 的普通消息结束不等同于整个任务成功。插件只在正常结束消息后，没有待处理工具、审批或证据缺口，且静默 3 秒时结束显示。单个工具失败不会直接表示整个任务中断。

内置文件采集只有 DeepSeek 提供审批事件，审批请求可能自动获准。Codex、Claude、Pi 当前内置采集不提供确认事件；任何 Agent 的外部 waiting_confirmation 均可显示为待确认。Cursor/Gemini 需要独立 Runtime 上报端，本项目不再包含它们的旧 Hook 采集器。

这些是现有格式的能力范围，不代表各工具所有版本、桌面入口、远程或 WSL 场景已经完成实机验证。

## 显示选择与时长

文件采集按待确认、调用工具、工作中排序，同级选择最近活动会话；活动优先于采集结束提示。

| 配置项 | 默认值 | 作用 |
|---|---|---|
| 完成提示 | 5 秒 | 采集和主动上报的任务完成提示 |
| 提醒显示 | 15 秒 | 采集和主动上报的任务中断、状态未知提示 |
| 工作超时 | 5 分钟 | 工作、工具状态没有新进展时转为状态未知 |
| 确认超时 | 30 分钟 | 待确认状态没有新进展时转为状态未知 |
| 主动上报显示 | 开启 | 独立控制所有外部上报的可见性 |

主动上报直接采用上报结果，不执行采集状态推断。有效上报优先于采集，多条上报以 Runtime 接收 ID 最新者优先。关闭工具采集勾选不会隐藏该工具的主动上报。

工作、调用工具和待确认的新有效上报刷新各自无进展超时，状态相同也可以刷新；重复接收 ID、SSE 心跳、采集活动和健康通知不刷新。工作、等待超时转为未知，按提醒时长显示。完成使用完成提示时长，中断、失败和未知使用提醒时长；同一来源会话轮次连续重复的相同结果不延长或重现提示。idle 或本地清除移除对应上报显示。

结果提示到期后从任务栏、悬浮提示、详情列表清除，再选择其他有效上报或采集状态。关闭上报显示只隐藏结果，计时仍继续；延长时长不会恢复已过期的结果，也不会撤销已经发生的超时。旧配置中的 reportedStateLeaseMs 和 runtimeDirectory 忽略，保存或升级安装后移除，其他显示偏好和四个时间参数保留。

## 启动与连接

- 插件安装目录：`<TrafficMonitor>\plugins\AgentStatus.dll` 和 `plugins\AgentStatus\`。
- Bridge 配置与日志：`%LOCALAPPDATA%\TrafficMonitorAgentStatus`。
- Runtime 默认运行目录：`%APPDATA%\AgentStatusRuntime`。
- 发现文件：Runtime 运行目录的 `private\connection.json`。无需手工复制令牌或固定端口。
- 插件后台程序由 TrafficMonitor 加载 DLL 后自动拉起，不创建独立登录启动项；Runtime 仍由自身安装器和计划任务管理。

0.2.5 起，直接复制 DLL 和完整 AgentStatus 文件夹后，启动 TrafficMonitor 并启用显示项目即可。DLL 在正常宿主回调中启动 Bridge，冷启动不等待后台就绪；桥接意外退出后按 5 秒间隔限制重试，避免反复启动。退出 TrafficMonitor 或卸载 DLL 会通知桥接退出，释放覆盖升级所需的文件。桥接不单独注册登录自启动；旧版指向 AgentStatusBridge.exe serve 的自启动项会在运行新版时清理。需要开机显示时启用 TrafficMonitor 自身自启动。

“发现服务并连接”保留为手动重试入口，不再是首次安装步骤。它等待 TrafficMonitor 已自动启动的 Bridge，然后请求重新发现服务；不创建脱离宿主运行的后台进程。后台自动读取当前用户默认目录的连接文件，必要时调用标准安装位置的 Runtime start。没有服务时显示“未发现Runtime服务”，不下载或安装 Runtime，也不提供目录选择。


只读凭据不会写入日志、UI 或 URL。断线、gap、实例换代及重连清空旧状态和上报计时，不查询 recent 恢复任务。SSE 45 秒无数据或心跳时断开，之后按 1、2、5、10 秒间隔重试。

## 排错命令

```powershell
$bridge = '<TrafficMonitor目录>\plugins\AgentStatus\AgentStatusBridge.exe'
& $bridge ping
& $bridge snapshot
& $bridge start
& $bridge stop
```

ping 检查显示 Bridge 的版本与进程，snapshot 查看连接及当前状态。stop 只停止 Bridge；start 等待 TrafficMonitor 自动启动 Bridge，需先运行并启用插件。TrafficMonitor 仍在运行时，stop 后桥接可能被自动恢复；准备覆盖更新时应退出 TrafficMonitor。

如果看不到状态，依次检查：Runtime 是否运行；详情是否显示“Runtime 已连接”；对应来源是否勾选；是否在订阅之后产生了新活动。主动上报还需检查独立开关、提示时长与无进展超时。连接异常时点击“发现服务并连接”。

日志位于 `%LOCALAPPDATA%\TrafficMonitorAgentStatus\diagnostics.log`，只记录脱敏的故障类别，不记录提示、工具参数、HTTP 正文或凭据。Runtime 自身日志在其运行目录的 private/service.log。

## 更新与回退

安装器先验证包内 SHA-256 清单，并将旧插件、配置和需清理的旧 Hook 保存到 `%LOCALAPPDATA%\TrafficMonitorAgentStatus\backups\<时间戳>`。然后替换本插件目录，清理活动目录里的过期文件，保留其他插件和配置。

升级到 Runtime 版本前遗留的 Claude/Cursor/Gemini Hook，仅在命令准确指向本插件安装目录时移除；相关清理脚本是安装流程的一部分。版本 2 的配置保留自定义选项，新增设置补默认值。回退前停止 TrafficMonitor 和 Bridge，恢复同一次备份中的程序与配置，再启动显示程序。
