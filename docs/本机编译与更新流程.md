# 本机编译与更新流程

本文档记录本机 `TrafficMonitorAgentStatus` 修改后的完整编译、覆盖安装和启动流程。每次修改代码后，都应重新编译，再把本次构建产物复制到 TrafficMonitor 的实际插件目录。

## 2. 一次完整更新

以下命令应在 PowerShell 中逐段执行。推荐先使用普通权限 PowerShell；只有复制目标目录提示拒绝访问时，才单独使用管理员 PowerShell 完成停止和复制步骤。

### 2.1 设置本次操作使用的路径

```powershell
Set-Location 'C:\Users\renxi\Desktop\TrafficMonitorAgentStatus'

$Toolchain = 'C:\Users\renxi\Documents\Codex\2026-09-10\wai\work\msvc'
$TrafficMonitorRoot = 'C:\Users\renxi\AppData\Local\Microsoft\WinGet\Packages\zhongyang219.TrafficMonitor.Full_Microsoft.Winget.Source_8wekyb3d8bbwe\TrafficMonitor'
$BuildRoot = 'C:\Users\renxi\Desktop\TrafficMonitorAgentStatus\build\x64'
$BridgeBuild = Join-Path $BuildRoot 'AgentStatus'
$PluginDirectory = Join-Path $TrafficMonitorRoot 'plugins'
$BridgeTarget = Join-Path $PluginDirectory 'AgentStatus'
```

### 2.2 停止正在占用文件的进程

覆盖 DLL 或接收器前，先退出 TrafficMonitor，并停止旧接收器：

```powershell
Stop-Process -Name 'TrafficMonitor' -Force -ErrorAction SilentlyContinue
Stop-Process -Name 'AgentStatusBridge' -Force -ErrorAction SilentlyContinue
```

这会中断当前状态显示，但不会修改 Agent 会话或用户设置。接收器停止期间发生的 Hook 事件不会补发；更新完成后，Agent 的下一次事件会重新建立状态。

### 2.3 重新编译全部组件

```powershell
.\build.ps1 -Toolchain $Toolchain -SelfContained
```

成功时最后会输出：

```text
Build output: C:\Users\renxi\Desktop\TrafficMonitorAgentStatus\build\x64
```

本命令会重新生成：

- `build\x64\AgentStatus.dll`：TrafficMonitor 原生插件。
- `build\x64\AgentStatusEmit.exe`：原生 Hook 事件入口。
- `build\x64\PluginProbe.exe`：插件探测程序。
- `build\x64\AgentStatus\`：完整的自包含接收器目录，其中也包含 Hook 使用的 `AgentStatusEmit.exe` 和 `AgentStatusJsonHook.cmd`。

如果提示找不到工具链，先确认 `$Toolchain` 下同时存在 `VC\Tools\MSVC` 和 `Windows Kits\10`。如果 `dotnet publish` 无法还原依赖，需要确认网络或 NuGet 缓存可用后重新执行，不能只复制上一次的旧产物。

### 2.4 核对关键产物

```powershell
$RequiredFiles = @(
    (Join-Path $BuildRoot 'AgentStatus.dll'),
    (Join-Path $BridgeBuild 'AgentStatusBridge.exe'),
    (Join-Path $BridgeBuild 'AgentStatusEmit.exe'),
    (Join-Path $BridgeBuild 'AgentStatusJsonHook.cmd')
)

$RequiredFiles | ForEach-Object {
    if (!(Test-Path -LiteralPath $_ -PathType Leaf)) {
        throw "缺少构建产物：$_"
    }
}
```

只有本次构建成功且上述文件齐全后，才继续覆盖目标目录。

### 2.5 备份当前安装文件

不要删除整个插件目录，也不要使用带清理或镜像删除效果的复制参数。更新前仅为当前文件创建带时间戳的备份：

```powershell
$Stamp = Get-Date -Format 'yyyyMMdd-HHmmss-fff'
$InstalledDll = Join-Path $PluginDirectory 'AgentStatus.dll'

if (Test-Path -LiteralPath $InstalledDll) {
    Copy-Item -LiteralPath $InstalledDll -Destination ($InstalledDll + '.backup-' + $Stamp)
}

if (Test-Path -LiteralPath $BridgeTarget) {
    foreach ($File in Get-ChildItem -LiteralPath $BridgeTarget -File | Where-Object Name -NotLike '*.backup-*') {
        Copy-Item -LiteralPath $File.FullName -Destination ($File.FullName + '.backup-' + $Stamp)
    }
}
```

备份文件留在原目录。确认新版本稳定后可手动逐个处理旧备份；不要批量删除目录。

### 2.6 覆盖新构建文件

```powershell
New-Item -ItemType Directory -Path $PluginDirectory -Force | Out-Null
New-Item -ItemType Directory -Path $BridgeTarget -Force | Out-Null

Copy-Item -LiteralPath (Join-Path $BuildRoot 'AgentStatus.dll') -Destination $InstalledDll -Force

foreach ($File in Get-ChildItem -LiteralPath $BridgeBuild -File) {
    Copy-Item -LiteralPath $File.FullName -Destination (Join-Path $BridgeTarget $File.Name) -Force
}
```

自包含发布目录中有多个运行文件，不能只复制 `AgentStatusBridge.exe`。应覆盖 `build\x64\AgentStatus` 顶层的全部文件，但不要删除目标目录中不属于本次构建的文件。

## 3. 正确的启动顺序

### 3.1 先以普通用户权限启动接收器

关闭管理员 PowerShell，打开普通 PowerShell，再执行：

```powershell
$BridgeExe = 'C:\Users\renxi\AppData\Local\Microsoft\WinGet\Packages\zhongyang219.TrafficMonitor.Full_Microsoft.Winget.Source_8wekyb3d8bbwe\TrafficMonitor\plugins\AgentStatus\AgentStatusBridge.exe'
& $BridgeExe start
```

这是重要的权限要求。Cursor、Codex CLI、Gemini CLI 等工具通常以普通用户权限运行；如果从管理员 PowerShell 启动接收器，它们可能可以执行 Hook，却无法连接高权限命名管道，表现为“Agent 正在工作，但任务栏没有内容”。

接收器应保持普通权限运行。即使 TrafficMonitor 本身以管理员权限运行，高权限 TrafficMonitor 仍可读取普通权限接收器发布的共享状态。

### 3.2 再按平时方式启动 TrafficMonitor

建议使用原来的桌面快捷方式或开机启动项启动 TrafficMonitor。也可以在普通 PowerShell 中执行：

```powershell
$TrafficMonitorExe = 'C:\Users\renxi\AppData\Local\Microsoft\WinGet\Packages\zhongyang219.TrafficMonitor.Full_Microsoft.Winget.Source_8wekyb3d8bbwe\TrafficMonitor\TrafficMonitor.exe'
Start-Process -FilePath $TrafficMonitorExe -WorkingDirectory (Split-Path -Parent $TrafficMonitorExe)
```

不要在执行文件覆盖的管理员 PowerShell 中顺手启动接收器。若必须以管理员身份运行 TrafficMonitor，也仍然要先从普通 PowerShell 启动接收器。

## 4. 更新 Agent Hook 配置

普通的插件或接收器代码更新不需要反复安装 Hook，因为 Hook 命令始终指向目标目录中的文件。只有以下情况需要重新运行安装脚本：

- 新增或删除 Agent 工具。
- 修改 Hook 事件列表或命令格式。
- TrafficMonitor 或插件目标目录发生变化。
- Hook 配置被其他程序覆盖或手动删除。

在普通 PowerShell 中执行：

```powershell
Set-Location 'C:\Users\renxi\Desktop\TrafficMonitorAgentStatus'

.\adapters\Install-AgentHooks.ps1 `
    -AgentStatusDirectory 'C:\Users\renxi\AppData\Local\Microsoft\WinGet\Packages\zhongyang219.TrafficMonitor.Full_Microsoft.Winget.Source_8wekyb3d8bbwe\TrafficMonitor\plugins\AgentStatus' `
    -UserProfileDirectory 'C:\Users\renxi'
```

脚本会更新：

- Codex CLI/TUI：`C:\Users\renxi\.codex\hooks.json`
- Gemini CLI：`C:\Users\renxi\.gemini\settings.json`
- Cursor：`C:\Users\renxi\.cursor\hooks.json`

脚本会保留其他 Hook，并在覆盖原配置前创建时间戳备份。Codex CLI 可能要求在 `/hooks` 中确认新增 Hook；Gemini CLI 或 Cursor 没有自动重载时，需要重启对应客户端。

Claude Code 使用自身已有 Hook 配置。Cursor 会兼容加载 Claude Hook，接收器会根据 Cursor 事件中的 `cursor_version` 把这类重复事件归一为 Cursor 来源。

## 5. 更新后的检查

### 5.1 检查接收器是否可连接

必须在普通 PowerShell 中执行：

```powershell
$BridgeExe = 'C:\Users\renxi\AppData\Local\Microsoft\WinGet\Packages\zhongyang219.TrafficMonitor.Full_Microsoft.Winget.Source_8wekyb3d8bbwe\TrafficMonitor\plugins\AgentStatus\AgentStatusBridge.exe'
& $BridgeExe ping
```

正常结果包含：

```json
{"ok":true,"version":"0.1.0","pid":12345}
```

如果出现超时或 `The operation was canceled`：

1. 停止所有 `AgentStatusBridge` 进程。
2. 确认当前 PowerShell 不是管理员窗口。
3. 再执行 `& $BridgeExe start`。
4. 重新执行 `ping`。

### 5.2 查看当前聚合状态

```powershell
& $BridgeExe snapshot
```

返回内容中的 `text` 是任务栏显示文本，`sessions` 是当前会话，`accepted` 和 `rejected` 分别表示已接受和拒绝的事件数。

### 5.3 实际客户端检查

更新接收器后，已经开始但发生在重启前的 Agent 状态不会自动恢复。向对应客户端发送一轮新请求，或等待下一次工具调用，任务栏应出现对应来源和状态。

如果 Cursor 仍无显示，可检查最新 Cursor Hook 日志：

```text
C:\Users\renxi\AppData\Roaming\Cursor\logs\<最新时间目录>\<窗口目录>\output_*\cursor.hooks.*.log
```

日志中应能看到 `AgentStatusEmit.exe --source cursor` 的执行记录。若 Hook 记录存在但每次耗时接近 1.5 秒，通常表示接收器未运行或权限级别不匹配。

## 6. 参数、配置和回退注意事项

- 用户设置保存在 `C:\Users\renxi\AppData\Local\TrafficMonitorAgentStatus\config.json`，不在插件安装目录中。正常覆盖构建文件不会清除显示来源、持续时间或自定义状态文本。
- 不要把 `config.json` 复制进构建目录，也不要在更新时删除 `%LOCALAPPDATA%\TrafficMonitorAgentStatus`。
- 复制 DLL 前必须退出 TrafficMonitor，否则 `AgentStatus.dll` 可能被占用。
- 复制接收器前必须停止 `AgentStatusBridge`，否则自包含运行文件可能无法覆盖或出现新旧版本混用。
- 不要只编译 C# 接收器后继续使用旧 DLL；标准流程始终运行一次完整的 `build.ps1`。
- 不要从旧的 `packaging\AgentStatus` 目录覆盖目标。日常开发更新以本次生成的 `build\x64` 为唯一产物来源。
- 不要使用会删除目标额外文件的镜像部署方式，也不要批量删除插件目录。
- TrafficMonitor、插件 DLL 和本机当前构建均为 x64，不能混入 x86 文件。
- 若新版本异常，可停止 TrafficMonitor 和接收器，把同一时间戳的 `.backup-...` 文件逐个复制回原文件名，然后按“普通权限接收器优先”的顺序重新启动。

## 7. 日常最短流程

代码修改后的最短可靠顺序是：

1. 停止 `TrafficMonitor` 和 `AgentStatusBridge`。
2. 在项目目录执行 `build.ps1 -Toolchain <本机工具链> -SelfContained`。
3. 确认 `build\x64\AgentStatus.dll` 和 `build\x64\AgentStatus\AgentStatusBridge.exe` 的修改时间是本次构建时间。
4. 备份并覆盖目标 DLL 及接收器目录中的文件。
5. 关闭管理员窗口，从普通 PowerShell 启动 `AgentStatusBridge.exe start`。
6. 按平时方式启动 TrafficMonitor。
7. 执行 `AgentStatusBridge.exe ping`，再使用实际 Agent 客户端观察结果。
8. 只有 Hook 定义或安装路径变化时，才重新运行 `Install-AgentHooks.ps1`。
