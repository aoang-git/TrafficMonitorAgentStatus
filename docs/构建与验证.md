# 构建与验证

使用 PowerShell 7、.NET 10 SDK、MSVC x64 和 Windows SDK：

```powershell
.\build.ps1 -Toolchain '<包含VC/Tools/MSVC及Windows Kits/10的目录>' -SelfContained
.\tests\Integration.ps1 -BuildDirectory .\build\x64
.\tests\Installation.ps1
```

每次原生构建先清空已确认位于本仓库的 build/x64，发布同版本 dist 目录也重新生成，避免残留旧上报程序。脚本构建 DLL、原生 ABI 探测器和 Bridge，生成自包含发布目录、ZIP、包内 SHA256SUMS 和 ZIP 校验值。

`dotnet run --project tests/StateTests.csproj` 执行状态和真实回环 HTTP/SSE 测试；Integration.ps1 在此基础上运行原生 DLL 探测，覆盖共享内存、API 6、并发读取和重复加载卸载。测试使用随机 TMAS_INSTANCE、独立 TMAS_DATA_DIR 和模拟 Runtime，不读写已安装 Runtime，不修改真实 Agent 记录。沙箱禁止命名管道时需在普通 Windows 用户环境执行。

检查包括：并行工具、确认解除、旧轮次、结束和超时、来源筛选、文案热加载、健康降级、缺口、SSE 边界、重复消息、心跳超时、401 凭据轮换、epoch 变化及目录切换。正常结束界面不显示判断依据。

Installation.ps1 使用临时用户配置和模拟 TrafficMonitor 目录，传入安装器的 UserProfileDirectory、DataDirectory、SkipStartup、SkipLaunch 参数，检查精确 Hook 清理、备份、其他配置保留及重复安装。安装器不读取或修改 Runtime。

本机实机验收采用只读订阅，观察订阅之后的自然新增活动，不把 recent 或历史文件当作当前状态，也不向现有 Runtime 注入测试记录。长期稳定性和各 Agent 版本兼容性仍须单独验证。
