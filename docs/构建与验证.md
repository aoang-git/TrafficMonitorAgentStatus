# 构建与验证

使用 PowerShell 7、.NET 10 SDK、MSVC x64 和 Windows SDK；标准 Visual Studio 安装自动发现工具链：

```powershell
.\build.ps1 -SelfContained
.\tests\Integration.ps1 -BuildDirectory .\build\x64
.\tests\Installation.ps1
.\tests\ReleasePublishingExit.ps1
```

自带工具链继续支持 `-Toolchain '<工具链目录>'`，分开安装的 Windows SDK 可用 `-WindowsSdk '<Windows Kits/10目录>'` 指定。`global.json` 将 SDK 限定在 .NET 10 的稳定版本。推送 main 和版本标签的自动构建、发布规则见[自动构建与发布](自动构建与发布.md)。

每次原生构建先清空已确认位于本仓库的 build/x64，发布同版本 dist 目录也重新生成，避免残留旧上报程序。脚本构建 DLL、原生 ABI 探测器和 Bridge，生成自包含发布目录、ZIP、包内 SHA256SUMS 和 ZIP 校验值。

`dotnet run --project tests/StateTests.csproj` 执行状态和真实回环 HTTP/SSE 测试；Integration.ps1 在此基础上运行原生 DLL 探测，覆盖共享内存、API 6、并发读取和重复加载卸载。测试使用随机 TMAS_INSTANCE、独立 TMAS_DATA_DIR 和模拟 Runtime，不读写已安装 Runtime，不修改真实 Agent 记录。沙箱禁止命名管道时需在普通 Windows 用户环境执行。

检查包括：并行工具、确认解除、旧轮次、结束和超时、来源筛选、文案热加载、健康降级、缺口、SSE 边界、重复消息、心跳超时、401 凭据轮换、epoch 变化及服务重新发现。正常结束界面不显示判断依据。另以可控单调时钟验证主动上报的状态映射、独立筛选、来源隔离、最新优先、活动续时、四类时间边界、重复结束抑制及配置变更不恢复过期项，并通过模拟 SSE 验证上报与采集隔离、到期回退、自动发现/启动、手动重连和界面开关生效。

Installation.ps1 使用临时用户配置和模拟 TrafficMonitor 目录，传入安装器的 UserProfileDirectory、DataDirectory、SkipStartup、SkipLaunch 参数，检查精确 Hook 清理、备份、其他配置保留及重复安装。安装器不读取或修改 Runtime。

本机实机验收采用只读订阅，观察订阅之后的自然新增活动，不把 recent 或历史文件当作当前状态，也不向现有 Runtime 注入测试记录。长期稳定性和各 Agent 版本兼容性仍须单独验证。

## 目录保留与清理

源码保留 bridge、plugin、tools 和 tests。tests 中的模拟 Runtime、上报计时测试和 ABI 探测器均由正式回归入口使用，不属于一次性测试文件。Remove-LegacyHooks.ps1 由安装器调用，负责精确清理升级前遗留的 Hook，仍属于有效安装组件。

build、dist、各项目 bin/obj 都是生成产物。仓库不提交它们；只需在 dist 保留当前版本发布包及校验文件；旧版包、旧启动快捷方式、编译缓存和截图临时目录可清理。本机个性化工具配置及已安装程序的回退备份不随项目目录清理删除。

0.2.3 增加 Runtime 发现和启动的隔离测试：未安装、后安装、健康复用、启动失败、就绪超时、显式重试、协议不兼容和取消。安装回归验证删除旧目录/租约字段并保留四个时间配置。界面检查使用独立 TMAS_INSTANCE 和 TMAS_DATA_DIR，不向真实 Runtime 注入事件。
